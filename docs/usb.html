01

它是什么，为什么需要它

What & Why

USB（Universal Serial Bus，通用串行总线）1996 年由 Compaq / DEC / IBM / Intel / Microsoft / NEC / Nortel 七家联盟推出， 动机简单粗暴：PC 背面接口太多了。串口鼠标一个 RS-232、打印机一个并口、键盘 PS/2、 扫描仪一张 ISA 卡——每个外设一套接口、一张驱动盘、一次重启。USB 的答案是 一个口 + 一套协议 + 一套类驱动：即插即用、热插拔、可级联（hub 展开成树，最多 127 个设备）。

物理上它极其朴素：四根线——VBUS（+5V 电源）、D+/D−（差分数据对，90Ω 特性阻抗）、GND。 但协议上它做完了所有脏活：插入检测、设备识别（枚举）、地址分配、带宽调度、错误重传、电源预算管理。 与 UART 那种「裸对裸」的点对点不同，USB 是主机中心制（host-centric）： 一切传输由主机发起，设备只能应答——这个不对称性正是它能做到「插上就能用」的根源，也是 「两个 U 盘直接对拷为什么不行」的答案（需要 OTG 双角色）。

嵌入式工程师和 USB 打交道有三种姿势：做设备（MCU 跑 USB CDC 虚拟串口 / HID 键盘 / MSC U 盘）、 做主机（网关挂 4G 模组、读 U 盘、接摄像头）、做供电（Type-C/PD 快充受电或供电）。 三种姿势共用同一套底层：差分对上的 NRZI 位流、令牌-数据-握手三段式事务、以及 07 节要算的供电账本。

版本演进记住一条主线：每代都向后兼容同一根线。USB 1.1（LS 1.5Mbps / FS 12Mbps）→ USB 2.0（HS 480Mbps，仍是那四根线）→ USB 3.x（SS 5/10/20Gbps，加了两对超高速差分线 + 地）→ USB4 / Type-C（40Gbps，隧道化协议、可翻转插头）。供电侧同步进化：100/500mA → BC1.2 → Type-C 3A → PD 240W。

FACT · 01

四线分工 VBUS D+ D− GND

电源一根、地一根、数据挤在两根差分线上——半双工分时双向。USB 3.x 另加 SSTX/SSRX 两对，才实现全双工。

FACT · 02

枚举 ENUMERATION

插入后 1 秒内的谈判：读描述符→分配地址→加载驱动（05 节实验室）。你看到的「叮咚」声就是它成功的欢呼。

FACT · 03

不对称 HOST-CENTRIC

主机开口设备答话。设备与设备不能直连——除非一方切换成主机（OTG / Type-C DRP 双角色）。

FACT · 04

类驱动 CLASS DRIVER

设备自报家门「我是 HID 键盘」，操作系统内置驱动直接接管——免驱的秘密是「按类不按厂」。

02

连接器家族与线缆解剖

Connector Zoo & Cable

协议三十年没换内核，连接器却换了四代：Type-A/B 的机械防呆（插反了插不进）到 Micro-B 的易碎舌片，再到 Type-C 干脆把「防呆」改成「无呆」——对称触点，正反都能插。 线缆内部则是一门传输线工程：90Ω 差分阻抗、双绞、屏蔽，一样都不能省。

1996

Type-A / Type-B 经典双雄

STANDARD
机械防呆的始祖：矩形插头只能从一个方向插入（虽然人人都要试两次）。A 型坐在主机/hub 上，B 型给打印机等「纯设备」——不对称的连接器对应不对称的协议。USB 3.0 的 SS 版在舌片背面加了一排 5 触点。
2000/2007

Mini-B / Micro-B 与 ID 脚

MINI · MICRO
移动时代的 5 pin 方案，第 4 脚 ID 是 OTG（On-The-Go）的角色开关：ID 悬空 = 设备（B 口），ID 接地 = 主机（A 口）——手机插 U 盘就靠这根脚让手机变主机。Micro-B 舌片易断是那一代人的共同记忆，最终被 Type-C 取代。
2014

Type-C · 无呆对称 24 pin

FLIPPABLE
中缝一圈 24 触点、完全旋转对称：插头翻转 180° 后 TX1 对上 RX2、CC1 对上 CC2——每一组信号都有镜像备份。CC 线兼职三职：方向检测（Rp/Rd）、角色判定、PD 通信（BMC 码流）。CC 没接 Rd 的板子插上是不会通电的。
CABLE

线缆解剖 · 90Ω 差分工程

TRANSMISSION LINE
D+/D− 必须等长、双绞、控阻抗 90Ω——差分对的抗共模能力建立在两条线看到同样的噪声上（03 节）。线缆越长，5V 在线阻上的压降越狠：劣质线 0.5m 能掉 0.4V，2A 充电直接变慢充。5A 线缆里有 e-marker 芯片，经 CC 向两端申报电流能力。
PINOUT

Type-C 触点对称图 · 翻转后谁对谁

REVERSIBLE MAP
这张图解释 Type-C 「无呆」的工程代价：24 个触点里一半是镜像备份。方向检测由 CC 完成后，收发器切换到实际接通的那组差分对；D+/D− 是唯一原生对称的低速对（图为插头视角：A 面 CC 引脚、B 面 VCONN 供电给线内芯片；插座侧两根分别叫 CC1/CC2）。VBUS/GND 多针并联是为了 5A 大电流（电源页的电源树思维）。
03

差分信号与 NRZI 实验室

Differential & NRZI Lab

D+/D− 上跑的是一对互补信号：J 态 D+ 高 D− 低，K 态相反，SE0 双低用来发包尾与复位。 数据用 NRZI 编码（遇 0 翻转、遇 1 保持）——连续的 1 会让电平长时间不动、接收端失同步，于是又加了一条 位填充 铁律：连发 6 个 1 必须强插一个 0。切下面的字节，逻辑分析仪逐位拆解给你看。

FS 12 Mbps · 发送序 LSB-first · 初始态 J
STATES

J / K / SE0 三态

BUS STATES
总线上永远只有三种物理态。主机保持 SE0 超 10ms 就是复位信号——枚举的第一脚（05 节）。LS/FS 用不同的上拉位置报身份：FS 设备把 D+ 拉高、LS 拉高 D−，主机看哪根线被拉起就知道对方跑多快。
STUFF

位填充 · 六连一强插零

BIT STUFFING
NRZI 的死穴是长 1 串（1 = 保持 = 没有时钟信息）。位填充从发送方向「治好」它：连 6 个 1（连续 6 位不翻转）后插入一个 0——正好制造一次翻转。接收端数到 6 个 1 后自动丢弃下一位——两端的规则对称，数据无损。
90Ω

差分抗共模的数学

COMMON MODE
两根线紧贴双绞，外部噪声在两根线上几乎同相（共模）；接收端做差，噪声项相减抵消、信号项相加翻倍——信噪比白赚一倍。前提是两线等长、对称、阻抗连续：90Ω ±15% 差分阻抗 是硬指标，过孔和桩线都是它的敌人。
遇 0 翻转 · 六一插零NRZI + BIT STUFFING

USB 2.0 的物理层编码一句话说完了：NRZI 编码 + 位填充。0 = 翻转、1 = 保持；连 6 个 1（连续不翻转）强插一个 0 制造翻转，保证时钟可恢复。 注意字节序是 LSB-first——0x55 在线上是 1010… 从低位发起，抓逻辑分析仪别把位序读反（这是新手解析 USB 流量最常见的翻车点）。

04

包结构 · 三段式事务与四种传输

Packets & Transfers

总线上一切皆包（packet）：前导 SYNC 同步、PID 标明身份、正文带 CRC 校验、SE0 收尾。 包拼成事务（transaction）——主机发令牌（token）、一方发数据（data）、另一方回握手（handshake）， 三段一锤定音。而传输（transfer）由若干事务组成，按 QoS 分成四种。

FORMAT

三种包的解剖

SYNC · PID · CRC · EOP
PID 低 4 位 + 高 4 位取反——自带校验，令牌包里 ADDR 7 位（127 设备上限的出处）+ ENDP 4 位（16 端点）。 NAK 是 USB 的「流控灵魂」：设备来不及就回 NAK，主机稍后再来——没有 NAK 机制就没有即插即用的从容。
传输类型带宽时间保证重传典型用途
Control 控制保留 10%尽力是枚举 · 配置（EP0 必备）
Bulk 批量剩余全给无是U 盘 · 虚拟串口 · 打印
Interrupt 中断保留（小）bInterval 轮询是键盘鼠标 · 触摸
Isochronous 同步预约定每帧固定时隙不重传音频 · 摄像头

主机每 1ms 发一帧 SOF 包（High-Speed 细分为 125µs 微帧）当总节拍器；四种传输在帧内按 「控制 → 中断 → 同步 → 批量」的优先级瓜分带宽——批量传输吃的是剩饭，这正是 06 节计算器里 「标称 480Mbps、实测只有 30–42 MB/s」的第一个原因。

枚举状态机实验室 · 插上之后的 1 秒

Enumeration Lab

「叮咚」一声的背后是一套严密的谈判：D+ 上拉暴露身份 → 复位 → 以地址 0 应答 → 领地址 → 交描述符 → 配置生效 → 驱动绑定。点下面七步，看每一步总线上真实发生的事务和描述符内容。

地址 0 · 报家门 · 领新址ADDR 0 → SET_ADDRESS → CONFIGURED

所有用设备都以地址 0 起步——所以两个设备同时上电会撞地址，主机复位完一个处理一个。 描述符是一张嵌套的身份证：设备 → 配置 → 接口 → 端点，主机读完才知道「这是个什么、怎么说话」。 枚举失败十有八九卡在 EP0 的 64 字节第一次读（09 节踩坑 1）。

FS

为什么 FS 只有 1 MB/s

12M → 1M
FS 的 12Mbps 里，批量传输最多拿到 81%（19×64B/帧）；剩下被令牌/握手/CRC/帧间隙吃掉。这就是「标称÷10 ≈ 实际」的 FS 版。
HS

HS 为什么是 30–42 MB/s

480M → 40M
HS 微帧 125µs 能塞 13×512B，线速利用率理论 89%（53.2MB/s）；但真实主机的中断延迟、队列调度、缓存抖动再砍一刀。想逼近上限要调大 URB 队列深度、合并传输。
SS

SS 全双工与 8b/10b

FULI-DUPLEX
SS 加了独立收发对，全双工 + 异步流控（ packets 带 SEQ 与 ACK 回执链）。代价是 8b/10b 编码先吃 20%：5Gbps 毛速 = 4Gbps 数据。10Gbps 的 Gen2 换 128b/132b（仅 3% 开销）。
CHIRP

HS 握手 · chirp 鸟叫

HIGH-SPEED DETECT
HS 设备插上后先装成 FS（D+ 上拉），复位期间用 chirp 序列「对暗号」——双方都亮出 HS 肌肉才切 480Mbps、撤掉上拉改用 45Ω 端接。这段唱不上就静默降级，用户毫无感知。
07

供电协商实验室 · 从 100mA 到 240W

Power Negotiation Lab

USB 的供电是谈判制：没谈判就只有一档可怜的默认电流。四个场景走完三代供电体系—— USB 2.0 的 unit load 账本、BC1.2 的 D+/D− 短接识别、Type-C 的 Rp/Rd 分压定电流、 USB PD 在 CC 线上谈电压谈功率。左边电路在走流，右边示波器在读数。

未协商 · 100 mAUNIT LOAD DISCIPLINE

USB 2.0 的 unit load = 100mA：枚举完成前设备最多抽 1 个 unit load，配置（SetConfiguration）之后 才允许用到描述符 bMaxPower 申报的额度（最高 500mA）。跳过谈判硬抽大电流，轻则主机限流断口 （dmesg 报 over-current），重则劣质 hub 电源互搏。Type-C 时代同理：CC 上的 Rp/Rd 没握上手，一个电子都不会流。

USB 2.0

unit load 账本

100 / 500 mA
未配置 100mA → 配置后按 bMaxPower 最高 500mA（5×unit load）；USB 3.x 上调为 150/900mA。VBUS 标称 5V±5%，到设备端（含线阻压降）最低允许 4.5V。自供电设备必须在配置描述符里如实申报，并在断开 VBUS 时妥善处理。
BC 1.2

充电口识别

SDP · CDP · DCP
SDP（标准数据口）按上面账本；DCP（专用充电口）把 D+ 与 D− 短接告诉设备「我是充电器，别枚举」，电流放宽到 1.5A+；CDP 两者兼顾（先探测后通信）。苹果/高通的私有快充在 D+/D− 上叠电压挡位，是同一根线的方言变体。
TYPE-C

Rp/Rd 分压表

CC VOLTAGE TIERS
电源端 Rp 上拉（5V 经 56k/22k/10k），设备端 Rd=5.1k 下拉，CC 电压分出三档电流能力：0.42V→默认(500mA@USB2)、0.94V→1.5A、1.69V→3A。双 CC 线保证正反插；有源线缆的 e-marker 芯片挂另一根 CC（VCONN）上报 5A 能力。
PD

USB PD 功率阶梯

POWER DELIVERY
PD 在 CC 线上用 BMC 编码谈合同：Source 广播能力（5V/9V/15V/20V 固定挡 + PPS 20mV 步进），Sink 点菜 Request，Source 应 Accept → 抬压稳定后发 PS_RDY 宣告生效。从 0.5W 到 240W（48V/5A），电压变更期间 VBUS 必须先回 vSafe5V 再爬升——大功率快充的仪式感。

设备侧 D+ 上拉（1.5kΩ→3.3V）缺失或上电时序错

主机靠 D+ 被拉高才发现 FS 设备。dmesg 一条都没有 = 上拉没生效：查软件控制的上拉 GPIO（STM32 的 USBD_Start 内部控制）、或固件在 VBUS 未稳定前就拉起 D+（要求 VBUS 检测或延时 ≥100ms）。

枚举
不完
device descriptor read/64, error -71/-110 → 信号或时序

第一次 GetDescriptor 只读 8 字节（探 bMaxPacketSize0），这条都失败说明 EP0 应答波形不对：D+/D− 不等长（>3mm）、没按差分走线、晶振精度差（FS 要求 ±0.25%）、或上拉电阻阻值错。降速测试：把固件配置成 LS 有时能「带病枚举」暴露问题。

高负载
掉线
枚举前抽大电流 → over-current 断口

设备一上电就开 LCD/4G 模组（抽 300mA），超过 unit load 上限，hub 限流开关直接断 VBUS，表现为「枚举到一半消失」。把大负载的使能挪到 SET_CONFIGURATION 之后（08 节 STM32 注释即此坑）。

插电脑
反向供电
自供电设备的 5V 直连 VBUS → 灌进主机

自供电（电池/适配器）设备把自家 5V 直接接到 VBUS 上，会向主机倒灌——违反规范且可能损坏口。用理想二极管/or-ing（电池页 RTC 备份同款电路）或干脆 VBUS 只做检测不取电。

HS 不稳
掉到 FS
90Ω 差分阻抗被破坏：过孔、桩线、劣质线

HS 眼图对阻抗连续极其敏感：D+/D− 中途打太多过孔、stub 线（比如中途挂 ESD 管走成 T 型）、或用了不控阻抗的线——chirp 对唱成功但数据误码，主机反复重试。ESD 器件选低结电容（<1pF）且贴连接器放。

Type-C
不通电
设备端没接 Rd（5.1kΩ×2 下拉）

Type-C 电源端看不到 CC 上的 Rd 就「不认识你」，VBUS 根本不上电——不是线坏不是口坏。受电板 CC1/CC2 各接一个 5.1kΩ 下拉到 GND（两个都要，因为不知道哪面朝上）。PD 受电还要考虑 CC 通信通路的复用。

休眠
掉线
USB Suspend：总线空闲 3ms 设备必须降到 2.5mA

笔记本省电挂起总线后，设备电流必须压到 2.5mA——电池产品要在固件里处理 suspend（停外设、进低功耗）并申请远程唤醒（resume signaling）。Linux 侧设备莫名消失，先查 power/control 的 autosuspend（08 节命令）。

长线
5V 掉压
线阻吃掉电压：0.5m 劣质线 @2A 能掉 0.4V

VBUS 最低 4.5V 是硬指标：2A ×（线阻 0.1Ω×2 来回）= 0.4V 已经出局。大电流场景用粗线（22AWG+）、短线，或干脆 PD 抬到 9V/20V 传输（同功率电流减半、压降减半——电源页高压输电逻辑）。
